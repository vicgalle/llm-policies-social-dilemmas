You are an expert game-theoretic AI designing policies for a multi-agent Sequential Social Dilemma (the Cleanup game).

## Environment Summary

- 2D gridworld (18x25 map). River area (left side) and orchard (right side) are separated by a stream.
- 10 agents. All agents run your exact same policy code simultaneously.
- Agents collect apples in the orchard (+1 reward each).
- Waste (pollution) accumulates in the river over time. If waste exceeds a threshold, apples stop spawning in the orchard.
- Episode length: 1000 steps.
- 9 actions: FORWARD(0), BACKWARD(1), STEP_LEFT(2), STEP_RIGHT(3), ROTATE_LEFT(4), ROTATE_RIGHT(5), BEAM(6), STAND(7), CLEAN(8).
- BEAM: Penalty beam (costs -1). Hit agents receive -50 penalty and are removed for 25 steps. (DO NOT USE THIS in a cooperative setting).
- CLEAN: Cleaning beam. Costs -1 reward. Removes waste in the beam's path.
- Movement: Agents can strafe in 4 cardinal directions without needing to rotate first. Rotation only matters for the direction of the CLEAN beam.

## Beam Geometry (Length 5, Width 3)

When firing CLEAN or BEAM from `(r, c)` facing a specific orientation, the affected cells are:
- North (0): rows `r-5` to `r-1`, cols `c-1` to `c+1`
- East (1): rows `r-1` to `r+1`, cols `c+1` to `c+5`
- South (2): rows `r+1` to `r+5`, cols `c-1` to `c+1`
- West (3): rows `r-1` to `r+1`, cols `c-5` to `c-1`

## Winning Strategy & Optimization Guidelines

To maximize the collective team reward, you must implement a strict, permanent division of labor. Dynamic role switching causes agents to constantly walk across the entire map, wasting time and blocking each other.

1. **Permanent Role Allocation**: Assign exactly 2 agents (e.g., `agent_id < 2`) as dedicated "Cleaners" and the remaining 8 agents as dedicated "Gatherers". NEVER switch these roles.
2. **Gatherers**: Their exclusive job is to collect apples. They should use `bfs_nearest_apple` and `direction_to_action`. If no apples are reachable, they should `STAND` (7) and wait. They must NEVER attempt to clean or travel to the river.
3. **Cleaners (Spatial Partitioning)**: To prevent Cleaners from picking the same target spot and permanently blocking each other, mathematically divide their responsibilities by row. For example, Cleaner 0 ONLY evaluates target cells where `row < env.height // 2`, and Cleaner 1 ONLY evaluates target cells where `row >= env.height // 2`.
4. **Cleaners (Targeting & Firing)**: Do NOT evaluate every cell on the map or all orientations for firing positions. To avoid severe execution timeouts, Cleaners should exclusively search within `env.stream_cells_set` and `env.river_cells_set` (filtered by their assigned row partition), and ONLY evaluate the WEST (3) orientation. 
   - For each valid cell in their partition, calculate the waste cleared if firing West.
   - Pick the cell that clears the most waste (minimum 1). Tie-break by closest Manhattan distance.
   - Navigate to the chosen spot using `bfs_to_target_set`. Once there, check if orientation is 3. If not, output the correct rotation action (`ROTATE_LEFT` or `ROTATE_RIGHT`). If orientation is 3, fire `CLEAN` (8).
5. **Cleaners (Idle State)**: If no waste can be cleared in their partition, the Cleaner should pick a default idle spot on the stream within their partition and wait there, proactively facing West, ready for waste to spawn.
6. **Movement Efficiency**: Take full advantage of omnidirectional strafe movement. Keep orientation fixed while walking to save steps (`direction_to_action` handles this seamlessly). Only rotate when you are exactly on the firing spot.
