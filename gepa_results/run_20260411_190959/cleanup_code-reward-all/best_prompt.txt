You are an expert game-theoretic AI designing policies for a multi-agent Sequential Social Dilemma (the Cleanup game).

## Task

Write a policy that maximizes the **minimum per-agent reward** (Rawlsian welfare: maximize the worst-off agent's total return). All agents will run your exact same code simultaneously. There are 10 agents on a 18x25 map with ~103 apple spawns.

## Environment Summary

- 2D gridworld with two regions: a river area (left side) and an orchard (right side). A stream separates the two regions.
- Agents collect apples in the orchard (+1 reward each).
- Waste (pollution) accumulates in the river over time. If waste gets too high, apple spawning slows or stops.
- Episode length: 1000 steps.
- 9 actions: FORWARD(0), BACKWARD(1), STEP_LEFT(2), STEP_RIGHT(3), ROTATE_LEFT(4), ROTATE_RIGHT(5), BEAM(6), STAND(7), CLEAN(8)
- BEAM: fires a penalty beam (range 5, width 3). Costs -1 reward to fire. Hit agents receive -50 reward penalty and are removed for 25 steps (1 hit to tag).
- CLEAN: fires a cleaning beam (range 5, width 3). Costs -1 reward to fire. Removes waste cells in the beam's path, restoring clean river.
- Agents move in 4 cardinal directions WITHOUT needing to rotate first (strafe movement). Rotation only matters for the beam/clean direction.

## Strategic Guidance & Domain Constraints

To successfully maximize the minimum per-agent reward (Rawlsian welfare), you must perfectly equalize both the cleaning penalty and the apple-picking rewards among all 10 agents, while maintaining a clean river to ensure apples spawn. Because you lack persistent internal memory or reward-sharing mechanisms, you must rely on **Strict Spatial Partitioning**:

1. **Partitioning the Environment**: You must sort all `env.river_cells_set` by row (then column) and divide them as evenly as possible into `n_agents` chunks (e.g., using `index * env.n_agents // total_cells == agent_id`). Do exactly the same for all `env._apple_pos`. Agent `agent_id` is exclusively responsible for its specific river chunk AND its specific orchard chunk. Since the map is roughly symmetric, sorting by row creates contiguous horizontal "bands" of responsibility.
2. **Zero Redundancy & No Stealing**: An agent must ONLY clean waste that appears in its assigned river chunk, and ONLY pick apples that spawn in its assigned orchard chunk. Do NOT use the generic `bfs_nearest_apple` on the whole map. This completely eliminates redundant CLEAN penalties and perfectly equalizes apple rewards.
3. **Efficient Clean Targeting**: When waste appears in an agent's assigned chunk at `(wr, wc)`, it should navigate to a valid firing position to the right of the waste, face West, and CLEAN. Because the beam length is 5, a valid firing position `(cr, cc)` is any non-wall cell where `wc + 1 <= cc <= wc + 5` and `wr - 1 <= cr <= wr + 1`. 
   - **CRITICAL FIX**: Do NOT restrict valid firing positions to exclude the river. Waste can spawn at the far-left edge of the river (e.g., `wc = 0`). Because the beam length is 5, cleaning `wc = 0` REQUIRES standing at columns 1 through 5, which are INSIDE the river. If you exclude river cells from valid firing positions, far-left waste becomes permanently unreachable, stopping all apple spawns and ruining the score.
4. **Behavior Loop**:
   - Compute the agent's assigned river cells and assigned apple spawn cells. *(Tip: `env._apple_pos` and `env.apple_alive` are parallel arrays. When sorting `env._apple_pos`, keep track of the original indices to accurately query `env.apple_alive[original_index]`)*.
   - If waste exists in the assigned river cells, find the set of ALL valid firing positions for ALL such waste. Move toward the closest valid firing position using `bfs_to_target_set`. 
   - At any point, if you are mathematically within firing range and alignment of ANY assigned waste (facing West, distance 1 to 5 cells right of the waste, within 1 row), fire CLEAN immediately. If you are on a valid firing position but facing the wrong way, ROTATE to face West.
   - If the assigned river chunk is clean, look for alive apples strictly within the assigned apple chunk. If found, use `bfs_to_target_set` to move and collect them.
   - **Standby Setup**: If the assigned river chunk is clean AND no assigned apples are alive, move to a standby location strictly **IN THE ORCHARD** (e.g., at the average row and average column of the agent's assigned apple spawns). **Do NOT standby in the stream.** 10 agents standing in the stream will create a vertical wall that blocks pathing for everyone.
5. **Movement and Strafe**: Use `direction_to_action` combined with BFS step outputs to strafe towards targets without wasting steps rotating. Rotation should exclusively be used when setting up to fire a CLEAN beam. Never use the BEAM action.
